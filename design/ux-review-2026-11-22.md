# UI/UX review, 2026-11-22 (0.23.2)

A review of the whole app as a senior product designer and Android engineer would do it, asked
for by the user on 2026-11-22. **Nothing in it is implemented yet**: the user picks which
findings to build. When one is built, mark it here (✅ and the version) and record the decision
in `design/progress.md` as usual. CLAUDE.md's rules still apply to every fix: plan UI changes
first and wait for the OK, colours and sizes only through the token files (a new colour goes in
`mobile-tokens.json` → `color` with a Light and a Dark value; the desktop's colour files stay
unchanged), and check both themes at both sizes with the ThemeLab pictures.

How it was checked: the code (theme, navigation, every main screen), contrast computed from the
token files, and the release build 0.23.2 on the emulator (AVD `Medium_Phone_API_37.0`, 420 dpi)
at normal size, 200% text (`adb shell settings put system font_scale 2.0`), a larger display
size (`wm density 546`), PS1 Light, first run (all-files access set back to default), a
configuration change (`cmd uimode night yes`) and process death (`am kill` from the background).
Every emulator setting was put back afterwards. The key screenshots are in
`design/ux-review-2026-11-22/` (halved to 540 × 1200), named by pass: `A-` normal size, `B-` 200% text, `F-` first run.

## The app, as reviewed

A personal player for a large local library (about 27,000 songs) on the S24 Ultra and the FiiO
M21. Library: Artists → Albums → Album → tap a song → Now Playing; Search and the Playlists tab
beside it. The logo menu: Settings, Library Statistics, Listening History, Rescan Library, Theme,
Version (the update check). First run: all-files access, then the default Music folders are
scanned. Jetpack Compose with only the basic building blocks (`compose-ui`, `compose-foundation`;
no Material): every part is the app's own, driven by the desktop's token files. minSdk 33,
target and compile SDK 37. Navigation is the app's own saved back stack with predictive back.

## Summary

The parts that matter work well: playback, the library, back navigation, keeping your place
across a restart. The rough edges are in the labelling: Bit-Perfect's on/off is shown only by a
coloured dot, a few readouts are too faint in the Light theme, some error messages print raw
Java error text, and at 200% text several screens don't grow, so text gets cut off.

**No Critical findings: nothing blocks a task.** On the user's scale, the accessibility
failures (3–5) would count as Critical; they are marked Major because the user is the app's only
user and Dark is the default.

## Deliberate choices to keep

- **No Material 3 or dynamic colour**: matching the desktop is the point. The trade-off is that
  Material's parts come with screen-reader roles, a greyed look when disabled and minimum touch
  sizes built in, and the app's own parts don't yet. Findings 5, 7 and 10 come from that; one
  pass over `ui/Parts.kt` fixes most of it.
- **Hidden actions** (the logo as the only way into the menu, tapping the cover for its menu,
  tapping the names, long-pressing the heart): fine for the user, who knows they're there. Each
  has a screen-reader alternative except the letter strip, and the list scrolls without it.
- **Portrait only, English only** (strings in code, `supportsRtl="false"`): fine for a personal app.

## What's working well (don't break these)

- **Token discipline**: no hex colours or magic numbers in the screens, colours read at draw
  time, a theme switch changes everything at once.
- **Your place is kept**: the back stack is saved route by route. A configuration change and a
  process kill both brought back the Album screen with Back working through Albums to Artists,
  the scroll position (checked on a long playlist) and the paused mini player.
- **Predictive back** keeps each screen's state underneath; Edit Tags asks "Unsaved Changes"
  before leaving.
- **Edge to edge done right**: system bar icons follow the app's theme; the keyboard is handled
  in one place (`ScreenFrame`); Edit Tags' Save stays above the keyboard.
- **Lists are virtualised** with stable keys and `contentType` everywhere; thumbnails decoded at
  display size, cached on disk and in memory, prefilled after a scan.
- **The online screens** (Listening History, Genius, Lyrics, Update) have loading, empty, failure
  and tap-to-retry states; the update flow confirms first and checks the download before installing.
- **The SD card can come and go**: missing songs are greyed out, never deleted.
- **Playback controls** all have screen-reader names; Like and Shuffle say their state; the
  cover has a "Menu" action; swipe-to-skip has visible buttons as an alternative; the letter
  strip ticks under the finger.
- **The notification** uses the media session at low importance (no sound) and is visible on the
  lock screen; Lyrics keep the screen on only while timed lyrics play.
- **The screenshot tests**: about 400 ThemeLab pictures across both themes, both phones, 130%
  text and edge cases. Extending them is the cheapest way to lock fixes in.
